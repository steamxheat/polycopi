# polycopy-sim — симулятор копитрейдинга Polymarket

Бот следит за сделками выбранных кошельков (по умолчанию **goodfallen** и **almach**).
На каждую их сделку он в ту же секунду берёт **реальный стакан** и считает, по какой цене вошли бы вы.
Деньги виртуальные: старт $100, реальных ордеров нет, ключи и кошелёк не нужны.

Одновременно бот ведёт «идеального двойника» — те же сделки по цене лидера.
Разница между вами и двойником показывает, сколько стоит опоздание.

## Что нужно

- Сервер с Linux и **Python 3.9+**. Ставить ничего не надо: только стандартная библиотека.
- Регион, откуда Polymarket разрешён. Ближе всего к бирже (Лондон) — Дублин (AWS eu-west-1).
  Перед запуском проверьте, что торговля Polymarket легальна в стране сервера и в вашей.

## Запуск

```bash
# 1. Скопировать папку на сервер
scp -r polycopy-sim user@SERVER:~/

# 2. Проверить доступ и задержки (~15 секунд)
cd ~/polycopy-sim
python3 simbot.py check

# 3. Запустить (Ctrl+C — остановка, состояние сохраняется)
python3 simbot.py run
```

В `check` смотрите на:
- **Гео** — `blocked: false`.
- **Все строки OK.** Если упал только RTDS, поставьте в `config.json` `"use_rtds": false`, бот будет работать на опросе.
- **Время запроса стакана** — из Дублина должно быть десятки миллисекунд.

### Работа 24/7 (systemd)

```bash
sudo cp polycopy-sim.service /etc/systemd/system/
sudo sed -i "s#/home/USER#$HOME#; s#User=USER#User=$USER#" /etc/systemd/system/polycopy-sim.service
sudo systemctl daemon-reload
sudo systemctl enable --now polycopy-sim
journalctl -u polycopy-sim -f        # живой лог
```

Если без systemd, используйте `tmux new -s sim`, внутри `python3 simbot.py run`, затем `Ctrl+B D`.

## Результаты

```bash
python3 simbot.py report
```

Отчёт показывает:
- текущий счёт;
- реализованный PnL;
- PnL «идеального двойника» и **цену опоздания**;
- сколько сигналов скопировано и пропущено, с причинами;
- задержку до сигнала;
- проскальзывание в центах;
- комиссию, которую платит сам лидер.

Все сделки по строкам пишутся в `data/trades.csv` (открывается в Excel).
Сырые события пишутся в `data/recording.jsonl`.

**Как читать:** если через 5–7 дней реализованный PnL ≤ 0 или средний слип больше 1¢, копирование этих трейдеров не окупается.

### Пересчёт с другими настройками (без нового ожидания)

```bash
python3 simbot.py resim --max-slippage 0.01 --usd-per-trade 3
```

Берёт записанные сделки и стаканы и прогоняет их заново с другими параметрами.
Результат пишется в `data/resim/`, основной прогон не трогается.

## Несколько трейдеров (v2)

У каждого трейдера из `config.json` **свой виртуальный счёт** `start_cash` — так их можно честно сравнить.
Трейдер задаётся адресом или объектом с собственным интервалом опроса:

```json
"leaders": {
  "goodfallen": "0x0ca4…77a6",
  "primm": {"address": "0xd38b…5029", "poll_interval_s": 3}
}
```

Если запустить новую версию на старых данных (один общий счёт), бот сам:
- сохранит копию `data/state_v1_backup_<время>.json` и старый `trades.csv` как `trades_v1.csv`;
- разложит открытые позиции и реализованный PnL по трейдерам (по `trades.csv`);
- «идеального двойника» для старых трейдеров начнёт считать с момента перехода.

### Логи

| файл | что внутри |
|---|---|
| `pm2 logs polycopy-sim` | кратко: покупки, продажи, пропуски с причиной, итоги рынков, статус по каждому трейдеру раз в минуту |
| `data/bot.log` (+ `.1`…`.10`, по 20 МБ) | всё подробно: каждое исполнение лидера (цена, объём, $, его комиссия, задержка, источник), сводка стакана (bid/ask, спред, глубина в пределах лимита, время запроса, до конца рынка), дубли, попытки расчёта рынков |
| `data/decisions.jsonl` | одно решение = одна строка JSON со всеми полями (удобно анализировать) |

Отчёт по одному трейдеру: `python3 simbot.py report --leader primm`.

## Настройки `config.json`

| параметр | по умолчанию | смысл |
|---|---|---|
| `leaders` | goodfallen, almach | кого копировать: имя → адрес кошелька (proxyWallet) |
| `start_cash` | 100 | стартовый виртуальный баланс, общий на всех лидеров |
| `usd_per_trade` | 2 | сколько $ на один сигнал; поднимается до минимального ордера (обычно 5 акций) |
| `max_usd_per_trade` | 5 | если минимальный ордер дороже — сигнал пропускается |
| `max_slippage` | 0.02 | не платить больше цены лидера + 2¢ (лимит FAK-ордера) |
| `max_entry_price` | 0.97 | не покупать дороже 97¢ |
| `min_seconds_left` | 10 | не входить, если до закрытия рынка меньше N секунд |
| `group_window_s` | 3 | исполнения одного ордера лидера за N сек считаются одним сигналом |
| `taker_fee_coef` | 0.07 | комиссия тейкера = коэф × акции × p × (1−p) |
| `use_rtds` / `use_polling` | true / true | источники сигналов: лента WebSocket и опрос Data API, работают вместе |
| `poll_interval_s` | 1.5 | частота опроса Data API |

## Как это работает

1. **Сигнал.** Сделка лидера приходит двумя путями: из ленты RTDS (`wss://ws-live-data.polymarket.com`, все сделки площадки, фильтр по кошельку) и из опроса `data-api.polymarket.com/activity`. Берётся то, что пришло раньше, дубли отбрасываются. В отчёте видно, какой источник был быстрее.
2. **Цена входа.** Сразу запрашивается `clob.polymarket.com/book` (соединение держится открытым). Ордер имитируется как FAK: бот забирает уровни стакана до лимита «цена лидера + max_slippage», остаток отменяется.
3. **Продажа.** Если лидер продаёт, бот продаёт ту же долю позиции по бидам.
4. **Итог рынка.** После закрытия рынка бот берёт итог из `gamma-api.polymarket.com/markets` и рассчитывает позицию по 1 или 0.

## Ограничения

- **Время сделки.** Polymarket отдаёт время сделки лидера с точностью до секунды, поэтому «задержка до сигнала» ±1 с.
- **Комиссия.** Коэффициент 0.07 выведен из реальных сделок goodfallen. В отчёте есть строка с фактической комиссией лидера — если она стабильно другая, поправьте `taker_fee_coef`.
- **Мелкие позиции.** Ваш ордер почти не двигает стакан, поэтому симуляция для небольших сумм близка к реальности. На больших суммах реальность будет хуже.
- **Открытые позиции** в отчёте учитываются по себестоимости; PnL считается по закрытым рынкам.
